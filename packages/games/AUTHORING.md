# Как устроен модуль микроигры

Эталон — `src/stroop`. Любой новый модуль повторяет его структуру буквально.

```
src/<name>/
  manifest.json   данные, валидируются схемой при регистрации
  core.ts         чистое ядро: init + reduce, ни DOM, ни таймеров, ни Math.random
  index.ts        paramsForLevel, GameView на DOM, экспорт Microgame
```

## Ядро

```ts
export const core: GameCore<State> = {
  init: (config) => ({ rng: createRngState(config.seed), /* ... */ }),
  reduce: (state, input) => ({ state, effects }),
};
```

Правила, нарушение которых ломает воспроизводимость:

- **Никакого `Math.random`.** Состояние PRNG лежит в `state.rng`, используются чистые
  `rngNext`, `rngInt`, `rngPick`, `rngShuffle` из `@gamespace/core`.
- **Никакого `Date.now` и `performance.now`.** Время приходит в `input.tMs`.
- **Никаких `setTimeout`.** Отсрочка — эффект `{ kind: "schedule", timerId, afterMs }`,
  срабатывание приходит входом `{ kind: "deadline", timerId }`.
- **Состояние сериализуемо.** Только JSON-значения: ни `Map`, ни функций, ни классов.
- **Параметры запрашиваются на каждую пробу.** Эффект `requestParams` → вход
  `{ kind: "params", effective }`. Кэшировать параметры между пробами нельзя:
  оператор мог сдвинуть уровень. Исключение — механики, у которых зачётная
  единица блок, а не проба: `n-back` и `dual-load` строят весь поток стимулов
  при получении параметров, потому что менять глубину `N` внутри уже
  построенного потока бессмысленно. Такие модули запрашивают параметры раз на
  блок, и это должно быть отмечено комментарием в ядре.

Жизненный цикл, который ядро обязано поддерживать:

| вход | что делает ядро |
|---|---|
| `lifecycle` `enter` `main` | `emit block.start`, затем `requestParams` |
| `params` | строит пробу, `render`, `emit stimulus.presented`, `schedule` дедлайна |
| `action` | оценивает ответ, `cancel` дедлайна, `emit response`, `outcome`, `render` |
| `deadline` дедлайна | оценивает как пропуск: `correct: false`, `rtMs: null` |
| `deadline` межпробного интервала | `requestParams` или `complete`, если блок кончился |
| `protocol` `finish` | немедленное `complete` с итогом |

Обработать `protocol finish` обязана каждая игра, и это не формальность: так
протокол закрывает участок, когда его время вышло посреди блока. Сводка при этом
должна остаться осмысленной — частичный блок лучше оборванного.

`outcome` — единственный способ повлиять на сложность. Игра не знает политику и не
может понизить себе уровень. Для обучающих и probe-проб ставится `scored: false`.

## Манифест

Обязателен `levels.monotonicAxes`: перечисляются параметры, которые с ростом
уровня обязаны монотонно расти (`increases`) или падать (`decreases`). Контрактный
тест проверяет это по всем уровням, поэтому `paramsForLevel` не имеет права
менять направление на середине шкалы.

Длину блока объявляй отдельно от сложности:

```json
"blockLength": { "param": "blockMs", "unit": "ms" }
```

`unit: "count"` — блок кончается по числу проб или подблоков, `unit: "ms"` — по
времени. Хост показывает этот параметр отдельным контролом и разрешает менять его
при любой политике сложности, поэтому `paramsForLevel` обязана держать его
постоянным: длина блока — расписание, а не нагрузка. Исключение — задачи, где
длина блока сама объявлена монотонной осью, но тогда она обязана быть в
`monotonicAxes`, и контрактный тест это проверит.

Непрерывной механике счётный блок противопоказан: если зачётной единицей будет
эпизод, длина блока станет обратной функцией от умения участника — сильный
закроет его втрое быстрее слабого. Такой игре нужен `unit: "ms"`, и время
копится по шагам симуляции, а не по часам, чтобы пауза и прерывание блок
не съедали.

`interaction.actions` — логические действия, а не клавиши. Действие с выбором из
списка объявляется как `indexed: true`: клавиши раздаёт хост, номер приходит
в `payload.index`. Внутри игры никаких `KeyboardEvent`.

Набор клавиш для такого действия — 36 штук (цифровой ряд плюс буквы рядами
клавиатуры), чего хватает на самое большое поле, которое умеет нарисовать
платформа. Если варианты сами подписаны цифрами — как ячейки числового поля, —
ставь `indexKeyset: "letters-first"`, иначе клавиша «1» будет означать первую
позицию, а не ячейку с числом 1.

## Представление

`GameView` рисует то, что пришло в `render`, и не хранит состояния игры. Ответ
уходит через `ctx.input.submit(actionId, payload, "pointer")`, а количество
активных вариантов сообщается хосту через `ctx.input.setOptionCount(n)` — иначе
клавиши 1..9 не будут привязаны.

В `mount` обязателен `surface.setTask(...)`: описание задания видно в поле игры
всегда, а не только в каталоге.

## Непрерывные механики

Игра с физикой не получает особого механизма: ядро планирует шаг симуляции
обычным `schedule`, а на `deadline` считает `dt` из `tMs` входа и планирует
следующий шаг. Ограничь шаг сверху — иначе возврат из свёрнутой вкладки
телепортирует объекты. Ничего кроме `tMs` использовать нельзя: `Date.now()`
внутри ядра ломает и повтор, и виртуальное время.

Координаты держи в долях поля. Пиксели, плотность экрана и размер канваса —
дело представления: бери `CanvasStage` из `ui-web`, рисуй в `render` по
view-модели и не заводи собственный цикл анимации.

Помни о цене: шаг симуляции пишется в журнал как вход, поэтому непрерывная
механика плотнее дискретной примерно в пять раз. Если добавляешь такую игру,
заведи ей бюджет плотности в `tests/soak.test.ts`.

Управление удержанием объявляется в манифесте флагом `holdable`. Хост тогда
присылает `payload.phase` со значением `down` и `up`, а интегрировать удержание
по времени обязано ядро. Непрерывное наведение (мышь, палец) шлётся как обычное
действие с `payload.value` — представление обязано дросселировать дрожь, иначе
журнал распухнет на пустом месте.

## Клавиши на кнопках

Каждая кнопка подписывает свою клавишу. Не создавай кнопку через `el("button")`:
бери `OptionRow` для ряда вариантов и `ActionButton` для отдельной кнопки, обеим
передавай `ctx.input` — подпись берётся из фактической привязки, поэтому профиль
раскладки F/J/D/K меняет и управление, и надписи. Для кнопки не-indexed действия
укажи `actionId` у пункта ряда: иначе он подпишется номером варианта. Проверяет
это `tests/hints.test.ts`.
